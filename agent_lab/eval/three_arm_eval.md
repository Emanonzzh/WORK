## 五、这一轮里最难看的四条，先自己说

1. **`no_tool` 0/25 但 0 题编造**：25 题全部答"没有数据无法回答"。
   这既是好消息（铁律起效了）也是坏消息 —— 它说明对照组没被"编数字"打穿，
   我们赢在**能不能取到数**，不赢在**诚不诚实**。
2. **M02 是假链题**：PR000492 同时是"全局 |Δ| 第一"和"变化最大平台内 |Δ| 第一"，
   所以一次未过滤的 `contribution_breakdown(dimension="product")` 就撞得到同一行，
   `one_tool` 因此"过"了。它同时还踩了口径歧义（全平台合计 1,267.80 元 vs 该平台内 0 元），
   循环按后一种读法答，被我这边的标准答案判错。**两个错都是题目的，不是模型的。**
3. **`loop` 唯一那次"编造"是我判分的口径问题**：M08 它答 13,332,912.43，
   那是把三个月**相加**得来的推导值 —— 数是真数，只是不在任何一次返回值里。
   现在的判分器**分不清"推导"和"编造"**，这条不修就当 1 个假阳性。
4. **一次调用不是不能赢，是赢得侥幸**：`one_tool` 在 single 桶 10/10
   （全量第二轮是 10/10）—— 单步题上循环**没有任何优势**，多花两三次调用只多花钱。
   循环的价值只在 multi 桶：1/10 → 7/10。

## 六、复现性（一次意外得到的数据）

我误以为启动命令没发出去，重发了一次 —— 于是同一份配置（温度 0、同一题集、同一模型）
**同时跑出两份 75 行的全量**：`eval_20260925-015301.json` 与 `eval_20260925-015318.json`。
拿它们对拷，结果是"温度 0 就等于可复现"这个假设不成立：

| 对照项 | 两份一致的比例 |
|---|---|
| 答案**逐字**相同 | 13 / 75 |
| 工具调用次数相同 | 71 / 75 |
| `correct` 判定相同 | **74 / 75** |
| 总正确率 | `loop` 20/25 与 **21/25**；`one_tool` 11/25 与 11/25；`no_tool` 0/25 与 0/25 |

翻的那一题是 O05（开放题"哪个平台最该被追问"）：一份答「web网站」（因为它是唯一收入负增长的主力平台），
另一份答「微信公众号」（因为它是增长主力但质量差）—— **两种说法都站得住**，
只是第一份漏说了标准答案要求的那个退款率数字。工具次数不同的 4 行里，
O01 一份走了 4 步、另一份 1 步就收，两步以上都判对。

**所以引用这些数字时必须带上三条限定**：
1. 20/24 这种数带 **±1 的运行间噪声**，不是"稳定命中率"；
2. 温度 0 只保证不引入随机采样，**不保证复现** —— 服务端与并行路径都会漂；
3. **开放题（5 题）的判定本质不稳**，要报就报单步/多步两个客观桶，
   别把开放题的分数混进"循环更强"那句结论里。

## 七、题集本身的可信度装置

| 装置 | 作用 | 现状 |
|---|---|---|
| `--facts-only` | 25 题标准答案全部现调工具算，题文件里不许有业务数字 | 0 异常，合计最少 48 次调用 |
| `--probe-multi` | 拿 411 个"一次调用"候选逐题撞，撞得上的 multi 就是标签虚高 | 标签与事实不符 0 题，链式豁免 7 题 |
| `tests/test_eval_harness.py` | 判分器自己的正反用例（含"空回答不许判对""蒙对算编造""截断的 observation 仍算授权"） | 全绿 |
| `--rescore` | 判分口径改了就拿旧结果离线重打，不二次花钱 | 已用（本轮 75 行重打后与在线一致） |

判分口径：**correct = 必含数全部说到 + 该报的实体名报了 + （非开放题）没有冒出授权集外的大数**。
实体名这一项专治"靠枚举蒙对"：未过滤的分解会把每个商品的数都列出来，只比数字就会放过一次调用的臂。
